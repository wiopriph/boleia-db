# Миграции 0014 и 0015: исправления по находкам web-клиента

ТЗ: разделы 5 (машина состояний брони, no-show), 6 (RPC), 7 (коды ошибок), 12 (экраны водителя).
Источник: реальные экраны `boleia-web` против облачного проекта, ноябрь 2026.

## 0014_retry_clears_reason

`retry_payment` переводил бронь `payment_failed -> pending_payment`, но оставлял `cancel_reason` прошлой
неудачи (`payment_expired`, `PAYMENT_PHONE_MISMATCH`). После успешной оплаты клиент показывал причину
отказа рядом с оплаченным статусом. Теперь `cancel_reason` сбрасывается при повторной попытке.

## 0015_contract_fixes

| # | Находка | Причина | Исправление |
| --- | --- | --- | --- |
| 1 | `publish_trip` с заметкой > 500 символов падал без кода `BOLEIA` | длину проверял только check таблицы (`23514`) | проверка в RPC, `MESSAGE_TOO_LONG` (как в `update_trip`) |
| 2 | `upsert_vehicle` с местами вне 1-8 или годом вне 1980-2030 падал так же | то же, check таблицы | `SEATS_INVALID`, новый код `YEAR_INVALID`; проверка и при создании, и при изменении |
| 3 | `cancel_quote` обещал водителю счётчик по брони в `requested`, а `cancel_booking` её отклонял без счётчика | `refund_rule` не различал статус брони для водителя | для `requested` правило `driver_decline`, `counter = false`; quote и действие совпадают |
| 4 | `driver_wallet.earned_total_kz` рос после неудачной выплаты | суммировались все положительные строки `driver_balance`, включая `payout_failed` | считаются только строки `release:*` |
| 5 | `mark_no_show` засчитывал PIN отменённой брони | проверка "есть PIN другого пассажира" не смотрела на статус | PIN считается только у броней в `awaiting_confirm`, `completed`, `disputed`; то же в шаге cron "водитель не приехал", где отменённый PIN блокировал автоотмену |
| 6 | новый пассажир показывался с рейтингом 0,00 | в `my_bookings` не было числа оценок | добавлен `passenger_rating_count`; 0 значит "оценок нет" |

## Выяснилось по ходу

- Общий корень находок 1 и 2: ограничения таблиц дублируют правила RPC, но отвечают SQLSTATE `23514`
  без кода. Правило на будущее: любое check-ограничение на поле, которое приходит от клиента,
  повторяется проверкой в RPC с кодом `BOLEIA_*`. Нечисловой ввод (`"seats_total": "abc"`) по-прежнему
  даёт `22P02`: клиенты шлют типизированные значения, это ошибка программиста, а не пользователя.
- Находка 5 показала, что PIN можно ввести за 3 часа до выезда, а бронь после этого отменить.
  Сам PIN при отмене не стирается намеренно: это след для спора.
- Миграция снова собрана скриптом из `pg_get_functiondef` с точечными правками (см. 0013).
