# Миграция 0018: админка, деньги

ТЗ: раздел 11 ("Деньги: баланс по счетам ledger, очередь выплат и возвратов, выгрузка CSV за период").
Источник: второй проход админки `boleia-web`, ноябрь 2026.

| Функция | Кто | Что возвращает |
| --- | --- | --- |
| `admin_ledger_balances()` | admin (`NOT_ADMIN`) | строка на каждый счёт `ledger_account`: `balance_kz`, `entries`; счета без проводок с нулём |
| `admin_refund_queue()` | admin (`NOT_ADMIN`) | платежи с `refund_kz > 0` и `refund_ref is null`: плательщик, телефон, `provider_ref`, суммы, `refund_attempts`, `refund_failed_at`, `is_manual` |

Ledger не пишется: обе функции только читают.

## Зачем отдельные функции

- Баланс по счетам - сумма по всей таблице `ledger_entries`. Клиент деньги не считает и не должен
  выкачивать ledger постранично ради семи чисел.
- `payments` закрыт column grants (0003): `refund_attempts`, `refund_failed_at`, `refund_ref` и
  `provider_ref` клиенту не видны даже под admin. Без них админка не отличает возврат в автоочереди от
  застрявшего, а `admin_mark_refund_manual` на строке из автоочереди дал бы двойной возврат (Edge
  `payments-refund` дойдёт до шлюза следом). Расширять grant на всех authenticated ради админа не стали.

## Решения

- `admin_refund_queue` отдаёт обе части очереди: автоматическую (то же условие, что view
  `pending_refunds`) и ручную (`refund_attempts >= 3`, счётчик `refunds_manual` в `admin_stats`).
  Клиент показывает кнопку ручного возврата только при `is_manual`.
- `admin_mark_refund_manual` не менялся: проверки `refund_attempts` в нём по-прежнему нет, ограничение
  живёт в интерфейсе. Если понадобится жёсткий запрет, это отдельное решение с кодом ошибки в ТЗ.
- Возвраты - `returns table`, а не `setof jsonb`: типы попадают в `types/database.ts`.
- CSV за период функцией не делается: `ledger_entries` читаются админом под RLS, клиент листает их
  keyset'ом по `id` и собирает файл сам.

## Тесты

`supabase/tests/14_admin_money.test.sql`: доступ, строка на каждый счёт, сумма балансов 0 до и после,
возврат после оплаты с чужого номера в автоочереди, после трёх неудач в ручной и первым в списке,
совпадение со счётчиком дашборда, исчезновение после ручной отметки.
