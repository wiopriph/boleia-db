# Миграция 0024: контекст в уведомлениях

ТЗ: раздел 9 (уведомления), раздел 7 (контракт клиента), раздел 12 (экран уведомлений).
Источник: разбор ленты уведомлений web с Evgenii, 2026-11-24: строки не вели никуда, тексты без поездки,
одно и то же уведомление для водителя и пассажира вело на экран пассажира.

| # | Проблема | Решение |
| --- | --- | --- |
| 1 | уведомление не говорит, о какой поездке речь | `notify()` дописывает `origin_name`, `destination_name`, `departure_at` |
| 2 | двусторонние типы (`dispute_*`, `trip_cancelled`, `trip_reminder_24h`) неразличимы для сторон | `notify()` дописывает `role`: `driver` или `passenger` |
| 3 | `dispute_resolved` и `review_request` несут только `booking_id` | `trip_id` находится по брони |
| 4 | прочитал чат напрямую, а уведомления о сообщениях остались непрочитанными | `mark_read` гасит in-app `new_message` этого чата |

Контекст собирает `notification_context(user_id, payload)`, её зовёт `notify()`: 30 мест вызова не
правятся, новые типы получают контекст сами. Таблица "тип - экран" записана в `docs/api.md`
(`scripts/gen-api-doc.py`), по ней ведут и web, и Flutter.

## Тесты

`16_notification_context`: роль и маршрут у обеих сторон брони; `trip_id` по `booking_id`; посторонний
получатель без роли; payload без поездки не меняется; ключи события сильнее контекста; мусор в id не
роняет `notify`; `mark_read` гасит уведомления своего чата и не трогает остальные.

## Решения

- Контекст пишется в payload при создании, а не достаётся view при чтении: лента остаётся одним запросом
  к `notifications`, push и SMS получают те же поля. Цена: имя города и время - снимок на момент события
  (время выезда меняется только пока нет броней, так что расхождение редкое).
- `role` определяется для получателя, а не для события: админ, который сам водитель поездки, получит
  `driver`. Клиент выбирает экран сначала по типу (админские типы ведут в админку), потом по роли.
- Пассажир определяется по конкретной брони из payload; без `booking_id` - по любой его брони на поездке.
- Прочтение остаётся на клиенте поштучно (`mark_notifications_read`); автоматически гаснут только
  уведомления чата, потому что чат читают чаще с его экрана, чем из ленты.
- Старые уведомления не дополняются: клиент показывает их без строки маршрута.
- Realtime для ленты не добавлен: три подписки из раздела 7 остаются, счётчик обновляется pull-запросом.
